# 密封多单位拍卖与保证金清算（合成实现）

纯合成账户与虚构拍卖规则，**不连接任何真实金融服务**：无加密密封、真实支付、税费或信用授信。金额一律为**整数分**，账户/场次/标的均为虚构。

## 规则

- 每场卖出 `K` 个同质单位（1–10），每买家最多一个有效 bid；bid 含正整数数量、整数分单价、稳定 `bid_id`。
- 截止前可**完整替换**（更高 `revision` + 新冻结凭据）或**撤销**；截止后不可改标。
- 排序：单价降序、`bid_id` 升序，分配 `min(qty, 剩余)` 直到 `K` 用尽，允许最后一标部分成交。输入顺序不参与并列判定。
- 统一成交价 = **所有获配单位中的最低投标价**；无人获配则无成交价。
- 每买家订单额 = 获配数量 × 统一价；未成交单位不收费。
- 上限：最多 5 买家/场、每场 10 单位、本部署总计 3 场。

## 保证金口径

每个买家恒满足：

```
累计入金 = 可用 + 有效冻结 + 已扣款
```

- 冻结资金按 hold 绑定到**单一拍卖**，不能同时支持另一场投标。
- 结标后按**冻结结果**消费：获配者以统一价扣款并释放余量（扣款额不超过该 hold 冻结额），未获配者全额释放；hold 置为 `CONSUMED`/`RELEASED`，重复结算不再扣款。
- 数据库唯一索引 `ux_charge_once(auction_id, hold_id) WHERE kind='CHARGE'` 作为最后一道防线。
- 冻结余额在 `BEGIN IMMEDIATE` 事务内派生，两个连接争最后一分钱只有一个能成功。

## 一致性设计

| 关注点 | 实现 |
| --- | --- |
| 投标凭据核验 | 拍卖端在投标/冻结时直接读 `holds` 行，核对买家、场次、金额、`ACTIVE` 状态，绝不信任调用者自填“已冻结” |
| 撤标/换价原子性 | 撤销标记、新凭据安装、旧凭据释放处于**同一事务**，不存在旧款已释放但旧 bid 仍可结标的窗口 |
| 结标结果不可变 | 截止时一次性计算并写入 `settlements.allocations_json`；重开、重试、付款失败均复读同一份 |
| 响应丢失 | 每个写操作带 `request_id`，响应持久化在 `receipts`；相同请求重放返回已提交结果，不同请求复用 id 报冲突 |
| 结算续跑 | 每个 hold 的仓库操作使用确定性 `request_id`（`settle:<auction>:<bid>`），崩溃后任意调用者可按实际状态续做，不会双扣 |
| 待决状态 | `settlements.status` = `FROZEN → CLEARING → CLEARED`，部分结算可见且可继续 |

## 整箱交割（sealed_auction.fulfillment）

旧拍卖按同质**单位**结标，实际发放的是供应商预先封好的**整箱**样品。整箱永不拆开：某买家欠 `N` 单位，只能由件数之和**恰好等于 N** 的整箱组合交付。

| 关注点 | 实现 |
| --- | --- |
| 验收 | `receive_box`：稳定 `seal_id` + 正整数件数 + 到货批次 + 保管条件；同封签同内容重到只计一次（`duplicate=True`），异内容抛 `ContentConflict`，须 `restate_box` 显式更正 |
| 批次上限 | 每批 ≤ 24 箱、≤ 10 张凭单 |
| 受理 | `set_buyer_terms`（买家自有的可受理条件 + 取货截止日）+ `accept_box`（逐箱接受）。只有已验（`STORED`）且未取走的整箱可用；仅某买家接受的箱即成为其专属选项 |
| 报损/重验 | `damage_box` 将箱置为 `DAMAGED`；受损箱不可交付。`store_box`/`restate_box` 重验 |
| 换封 | `reseal`：旧箱 → 两新箱，**总件数守恒**，须指明原箱、新箱与授权买家（授权者自动接受新箱）。已提走/已上凭单的箱不可换 |
| 权利口径 | 每买家冻结所得 `awarded`；已取 + 在途凭单 + 剩余。买家仅受**全额一张**凭单，不允许半张先销权 |
| 联合排箱 | `issue_vouchers`：先最大化兑现总件数，再最大化兑现买家数，同分确定性取一个方案；箱不共享 |
| 逐单发单 | `issue_voucher_for_buyer`：无法凑齐全额时整单拒绝（`NotEligible`），绝不出半张 |
| 提货 | `pickup`：按冻结凭单逐箱核对**实际库存**；任一箱已报损/另一窗口已提走则整单中止（`InventoryMismatch`）。同 `request_id` 重放回执；已核销凭单的新请求被拒，同一权利/同箱不会交付两次 |
| 未知回执 | `get_pickup(request_id)` 按原单核实；`inspect_voucher` 对活库存复核凭单是否破损 |
| 退单 | `void_voucher`：未取走的凭单作废，箱回到可用库存；权利不变，可再发单 |
| 扣款隔离 | 交割只读冻结成交价，不重算、不改价；某买家取不到箱不会偷偷重定他人成交价 |
| 独立对账 | `reconcile_fulfillment` 从箱/接受/换封/凭单/出库原始记录独立重算 |

### 3 / 2 / 1 场景（`python3 -m examples.run_delivery`）

甲、乙、丙各获 3、2、1 件，可用箱为 3、2、1 件各一，3 件箱仅乙能收：

1. 乙只欠 2，含 3 件的箱**不能切开充数**，故乙不可用 3 件箱；
2. 甲拿 2+1 只能兑现一人；联合最优为**乙 2、丙 1**，兑现 3 件 / 2 人，甲仍欠；
3. 仓库将 3 件箱换封为 1 + 2 且甲授权后，重开排箱三人领齐 6 件（甲 1+2、乙 2、丙 1）；
4. 各凭单在窗口逐一交割并回执；重复/未知回执按原单核实，不重复交付。

## 复跑

```bash
python3 -m unittest tests.test_scenarios -v
python3 -m unittest tests.test_fulfillment -v
python3 -m examples.run_demo                       # 临时库
python3 -m examples.run_demo --db demo.sqlite3     # 持久库；多次运行自动命名空间隔离
python3 -m examples.run_delivery                   # 3/2/1 整箱交割演示
```

演示逐步打印：

1. 入金后可用余额；
2. 冻结如何占款、冻结不足如何拒绝投标；
3. 换价时旧 hold 原子释放、新 hold 生效；
4. 截止排序与统一价（及最后一标部分成交）；
5. 按统一价真实扣款、余量释放；
6. 重复结算不双扣；
7. 扣款已提交但响应丢失后，用同一 request id 续跑；
8. 排序解释；
9. 从原始事件重算每个买家的资金守恒；
10. 独立对账（账户、获配总数、扣款总额）。

## 已验证场景

`python3 -m unittest tests.test_scenarios` 覆盖：

- 并列截断由 `bid_id` 决定，而非输入顺序；
- 部分成交 + 统一价低于部分中标者报价，订单按统一价计；
- 撤标/换价原子替换冻结；
- 冻结不足、伪造凭据、跨买家/跨场次凭据、已释放凭据被拒；
- 同一 hold 不能支撑另一场投标；
- 重复结算、并发结算、扣款响应丢失后续跑均只扣一次；
- 截止后投标/撤销/修订被拒；扣款失败不改变冻结榜单；
- 两连接争最后余额仅一个成功；
- 空场无成交价；
- 限额与“每买家一个有效 bid”；
- 对账能从原始事件发现被删除的扣款。
